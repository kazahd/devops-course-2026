## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git: ветка — это просто указатель на коммит (файл размером ~41 байт).
Создание ветки — это запись одного файла, операция мгновенная.
Переключение между ветками тоже быстрое, потому что Git просто меняет
указатель HEAD.

В SVN: ветка — это физическая копия директории на сервере.
Чтобы создать ветку, SVN копирует все файлы проекта в новую папку,
что занимает время и место на диске. Переключение между ветками
требует повторной выгрузки файлов с сервера.

Вывод: в Git ветвление — это операция над метаданными (дёшево),
в SVN — операция над файлами (дорого).


## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система контроля версий.
Все коммиты отправляются на центральный сервер, поэтому нужна сеть.
Без интернета можно только просматривать локальные изменения,
но зафиксировать их в истории — только при подключении к серверу.

В Git коммиты делаются локально (в своём репозитории),
а потом синхронизируются с удалённым репозиторием через push.
Поэтому в Git можно работать полностью офлайн: делать коммиты,
создавать ветки, смотреть историю — и запушить всё, когда появится сеть.


## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

1. Legacy-проекты в банках и госсекторе.
Переписывать огромные системы на Git дорого и рискованно.
SVN продолжает работать, и его поддерживают.

2. Проекты с большими бинарными файлами (игры, медиа, CAD).
Git плохо работает с бинарниками: каждая версия файла хранится целиком,
репозиторий быстро разрастается. SVN хранит только изменения (diff),
поэтому эффективнее для больших бинарных файлов.

3. Команды с жёсткой централизацией и контролем доступа.
В SVN проще администрировать права: один сервер = одна точка контроля.
В Git у каждого разработчика полная копия репозитория, что сложнее
контролировать с точки зрения безопасности.

4. Проекты, где нужна частичная выгрузка (checkout только нужной папки).
В SVN можно выгрузить только нужную директорию из огромного репозитория.
В Git нужно клонировать весь репозиторий целиком (хотя есть sparse-checkout,
но это сложнее).

Вывод: SVN ещё жив в legacy-проектах, но все новые проекты стартуют на Git.
